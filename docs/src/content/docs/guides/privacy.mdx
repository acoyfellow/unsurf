---
title: Private by default
description: Every new trace is grant-gated. No bare URLs, no footguns. HMAC-signed grants, 7-day default TTL, surgical revocation.
---

**As of v0.4.0, every new trace is private by default.** The bare
`/r/<id>` URL returns 404 for any trace uploaded through the current
worker — the only shareable link is the signed `viewerUrl` returned in
the upload response. That eliminates the class of leakage where someone
pastes a trace URL into Slack, a PR description, or a log file and the
recording becomes world-readable forever.

```
old default:  GET https://trace.coey.dev/r/abc123xyz000                 → 200
new default:  GET https://trace.coey.dev/r/abc123xyz000                 → 404
              GET https://trace.coey.dev/r/abc123xyz000?vt=<grant>      → 200
```

Grandfathered bundles (uploaded before 0.4.0) keep working bare so
existing links don't break.

## Record (default = private)

```ts
import { recordLocal } from "unsurf/skills/record";

const result = await recordLocal({
  task: "log into cmux with yubikey",
  run: async (browser) => { /* … */ },
});

console.log(result.viewerUrl);
// → https://trace.coey.dev/r/<id>?vt=<exp>.<generation>.<signature>
```

The grant embedded in `viewerUrl` authorizes the viewer page *and*
every sub-resource (`/trace`, `/meta`, `/.json`, `/video-url`,
`/og.svg`) for 7 days. The video itself is signed separately with its
own short-lived token (unchanged behavior).

From the CLI — identical default:

```bash
unsurf record ./login-demo.ts --task "login"
# → prints a JSON blob with viewerUrl including ?vt=...
```

## Long-lived shareable: `visibility: "public"`

For "this demo is fine to publish; I just want a URL that doesn't
expire every week," pass `visibility: "public"`. Still grant-gated
(no bare URL), but the grant lasts **365 days** and is still revocable.

```ts
await recordLocal({
  task: "public demo",
  visibility: "public",
  run: /* … */,
});
```

```bash
unsurf record ./demo.ts --public
unsurf loop ./goal.json --north-star "done?" --public
```

There is no way, via the public API, to produce a new bare-URL trace.

## How grants work

Grants are `HMAC-SHA256(TRACE_SIGNING_KEY, "${id}|view|${generation}|${exp}")`
rendered as `${exp}.${generation}.${sig}`.

- **`id`** — the trace id.
- **`generation`** — integer counter in the trace's `meta.json`, starts at 0.
- **`exp`** — Unix timestamp. 7 days for private, 365 days for public.

The worker recomputes the HMAC on every request and compares the
generation to meta.json. Anything that doesn't match → 404. Existence
is never leaked.

## Revoke every outstanding grant

```bash
unsurf trace-revoke <id>
```

This:

1. Bumps `grantGeneration` in meta.json (0 → 1).
2. Mints a fresh grant at the new generation.
3. Returns the fresh `viewerUrl`.

Every previously-issued grant still carries the old generation in its
signed payload, so all of them 404 on the next request. No key
rotation, no KV for revoked tokens — one atomic meta.json write.

Works for both public and private traces.

## Grandfathered bundles

Bundles uploaded before 0.4.0 have no `visibility` field in their
stored meta.json. They keep serving bare `/r/<id>` so existing docs,
tweets, and cross-references stay alive. To lock one down retroactively,
re-upload with `visibility` set, or do a one-off R2 write that injects
the field. This is not automated — by design, so you don't accidentally
break an external link.

## Design notes

- **No accounts, no OAuth.** Grants ARE the auth surface. Trading a
  bearer token for another bearer token saves the caller nothing.
- **Short TTL + revocation beats long-lived secrets.** Leak a private
  grant, lose 7 days max — and revoke instantly.
- **Every new trace is gated.** The default eliminates the footgun
  instead of documenting around it.
- **One counter per trace.** Surgical revocation. Full signing-key
  rotation is still the nuclear option.
