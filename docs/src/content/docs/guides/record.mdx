## Why this matters

The typical "agent driving a browser" stack breaks on three things:

1. **WebAuthn / passkeys / YubiKey** — embedded webviews can't complete Apple's `ASAuthorizationController` ceremony cleanly against most IdPs. Real Chrome can.
2. **Federated corp browsers** — MDM policy blocks CDP. Trying to `--auto-connect` to your daily-driver Chrome triggers federation prompts every call.
3. **Text-based selectors** — `click "text=foo"` dies the moment a page has two matches. Then the surrounding script cascades into dead-air hangs.

The pattern below solves all three with one line, one dedicated profile, and a tick-gated loop.

## Prerequisites

```bash
npm i -g agent-browser
agent-browser install     # downloads Chrome For Testing (~200MB, one time)
```

<Aside type="note">
On macOS with MDM-locked work Chrome, `agent-browser` automatically uses the Chrome For Testing sandbox at `~/.agent-browser/browsers/`. Your daily-driver Chrome is never touched.
</Aside>

## The one-liner

```bash
agent-browser --headed --profile ~/.cmux-browser open https://my.cloudflare.dev
```

- `--headed` — visible window (drop it to run headless, which is what you want for video recording so the window doesn't steal focus)
- `--profile ~/.cmux-browser` — dedicated, persistent Chrome profile. Auth once, reuse forever.
- Same profile across runs = cookies, localStorage, and WebAuthn credentials all persist

### Proving the session persists

```bash
agent-browser --headed --profile ~/.cmux-browser open https://my.cloudflare.dev
# ... log in once, tap YubiKey, close ...
agent-browser close

# Fresh invocation, same profile, no login needed:
agent-browser --profile ~/.cmux-browser open https://my.cloudflare.dev
agent-browser get title
# → "Access: App Launcher"  (not the SSO page)
```

## The loop — why a one-shot script is a glass cannon

Naïve browser scripts look like this:

```bash
agent-browser open https://example.com
agent-browser click "text=Login"   # fails if "Login" appears twice
sleep 2                             # guess timing, hope for the best
agent-browser click "text=Submit"  # runs even if previous step failed
```

Every `sleep` is dead air on camera. Every text-selector is a landmine. Any failure cascades silently and the daemon can end up in an inconsistent state (you'll see `Command aborted`).

The fix is a **tick-gated loop**: each step is a tick, each tick gates on a **win flag** checked in the page, and each call has a hard timeout. The loop is the harness; the agent is dumb; the win flag is the fixed point.

<Steps>

1. **Pick a win flag per step** — a piece of DOM state that's only true when the step succeeded.

   ```js
   // Home: title contains "Jordan Coeyman"
   /Jordan Coeyman/.test(document.title)
   // On /projects page
   location.pathname === '/projects'
   // On /projects/unsurf page
   /\/projects\/unsurf/.test(location.pathname)
   // Scroll actually moved
   window.scrollY > 1500
   ```

2. **Wrap every subcommand with a hard timeout.** macOS doesn't ship `timeout(1)`, but `perl alarm` works everywhere:

   ```bash
   run() {
     perl -e '
       my $timeout = shift;
       my $pid = fork();
       if ($pid == 0) { exec(@ARGV); exit 127; }
       local $SIG{ALRM} = sub { kill 9, $pid; exit 124; };
       alarm $timeout;
       waitpid($pid, 0);
       exit($? >> 8);
     ' -- 10 "$@"
   }
   ```

3. **Each tick: take one action, check the win flag, retry on miss.**

   ```bash
   tick() {
     local state="$1" action="$2" check="$3"
     for i in $(seq 1 6); do
       eval "$action"
       if [ "$($check)" = "ok" ]; then
         echo "$state ✓"; return 0
       fi
       sleep 1
     done
     echo "$state ✗"; return 1
   }
   ```

4. **Wait for web fonts before recording** — `font-display: swap` means the page paints with a fallback face first, then hot-swaps once the real font loads. Recording before that moment captures the fallback face on video.

   ```bash
   agent-browser wait --fn 'document.fonts.ready.then(() => true)'
   ```

5. **Prefer URL-based and href-based selectors over text.** Text selectors are great for humans but brittle for agents — any page with more than one instance of a string breaks them.

   ```bash
   # Brittle:
   agent-browser click "text=unsurf"

   # Resilient:
   agent-browser click 'a[href="/projects/unsurf"]'

   # Even better when you know the destination:
   agent-browser open https://coey.dev/projects/unsurf
   ```

</Steps>

## The full script

This is the exact script that produced the video at the top of this page. It's also on disk at [`examples/loop-coey-tour.sh`](https://github.com/acoyfellow/unsurf/blob/main/examples/loop-coey-tour.sh) in the unsurf repo.

```bash
#!/usr/bin/env bash
# Loop-driven recording of a coey.dev tour.
# Each state is a "tick": take one action, verify win-flag, move on.
# Hard timeouts + retries + pulse lines. No hangs possible.

set -u
OUT=~/cloudflare/recordings/coey-tour
mkdir -p "$(dirname "$OUT")"
PROFILE=~/.cmux-browser
TIMEOUT=${TIMEOUT:-10}
MAX_TICKS=${MAX_TICKS:-6}
AB="agent-browser --profile $PROFILE"  # headless → no focus steal

pulse() { printf '[%s] %s\n' "$(date +%H:%M:%S)" "$*" >&2; }

run() {
  local label="$1"; shift
  perl -e 'my $t=shift; my $pid=fork(); if($pid==0){exec(@ARGV);exit 127} local $SIG{ALRM}=sub{kill 9,$pid;exit 124}; alarm $t; waitpid($pid,0); exit($?>>8)' \
    -- "$TIMEOUT" "$@"
}

eval_js() { run "eval" $AB eval "$1" 2>/dev/null; }
check_home()     { eval_js "/Jordan Coeyman/.test(document.title) ? 'ok' : ''"; }
check_projects() { eval_js "location.pathname === '/projects' ? 'ok' : ''"; }
check_unsurf()   { eval_js "/\\/projects\\/unsurf/.test(location.pathname) ? 'ok' : ''"; }
check_scrolled() { eval_js "window.scrollY > 1500 ? 'ok' : ''"; }

tick() {
  local state="$1" action="$2" check="$3"
  for i in $(seq 1 $MAX_TICKS); do
    pulse "$state tick $i/$MAX_TICKS"
    eval "$action" >/dev/null 2>&1
    local ok; ok=$($check | tr -d '"\r\n ')
    if [ "$ok" = "ok" ]; then pulse "$state ✓"; return 0; fi
    sleep 1
  done
  pulse "$state ✗ (gave up)"; return 1
}

run "close" agent-browser close >/dev/null 2>&1 || true
sleep 1

pulse "OPEN: homepage"
tick OPEN "run open $AB open https://coey.dev >/dev/null" check_home || exit 1

pulse "FONTS: wait for document.fonts.ready"
run "fonts" $AB wait --fn 'document.fonts.ready.then(() => true)' >/dev/null 2>&1

pulse "RECORD: start"
run "rec-start" $AB record start "$OUT.webm" >/dev/null 2>&1

pulse "NAV: click Projects"
tick NAV "run click $AB click 'a[href=\"/projects\"]' 2>/dev/null || run nav $AB open https://coey.dev/projects" check_projects || exit 1

pulse "SCROLL: down"
tick SCROLL "run scroll $AB scroll down 2400" check_scrolled || exit 1
run "wait" $AB wait 800 >/dev/null 2>&1

pulse "PICK: navigate to unsurf"
tick PICK "run nav $AB open https://coey.dev/projects/unsurf" check_unsurf || exit 1

pulse "STOP: recording"
run "rec-stop" $AB record stop >/dev/null 2>&1

ffmpeg -y -i "$OUT.webm" -c:v libx264 -crf 22 -preset fast -movflags +faststart "$OUT.mp4" >/dev/null 2>&1
echo "$OUT.mp4"
```

Run it:

```bash
chmod +x examples/loop-coey-tour.sh
./examples/loop-coey-tour.sh
# → ~/cloudflare/recordings/coey-tour.mp4
```

## Lifting this into unsurf proper

The shell script above is the procedural form. The declarative form is a [`proof-spec.v0`](/reference/config/) — observe, act, assert, with evidence. Every tick becomes a spec step; the win flag becomes an `assert`. Unsurf's `record()` skill (in `src/skills/record/`) already wraps any `BrowserHandle` callback into a video+trace+bundle with a canonical URL.

The logical next step is feeding a proof-spec into a loop runner so skills can be **refined and committed** across runs — [Lopopolo's workout-session pattern](https://twitter.com/lopopolo/): plant a flag, loop until captured, commit the refined skill, repeat until reliability metrics stabilize.

## Anti-patterns

- **Don't `--auto-connect` on an MDM-managed Chrome.** It triggers federation prompts every call; on Cloudflare work laptops this is instant death.
- **Don't use `text=...` selectors when you have a URL or an href.** Ambiguity is a hang waiting to happen.
- **Don't trust `networkidle` as a font-ready signal.** Use `document.fonts.ready`.
- **Don't try to record WebAuthn ceremonies via a native macOS shell's WKWebView.** Just use real Chrome — that's the whole point of this guide.
