After `scout` discovers a reusable seam, `worker` replays it directly over HTTP.

## Replay

```bash
curl -X POST $UNSURF_URL/tools/worker \
  -H "Content-Type: application/json" \
  -d '{
    "pathId": "your-path-id",
    "data": { "query": "jane" }
  }'
```

## Why use worker

Choose worker when:

- you already know the seam
- the browser does not add value for this repeat operation
- you want millisecond-scale direct calls instead of a fresh UI walk

Choose the browser runtime when:

- the user session itself matters
- the action is visual or interaction-heavy
- you want a reviewable recorded proof

## Authenticated replay

Worker can receive explicit request headers:

```json
{
  "pathId": "path_abc",
  "headers": {
    "Authorization": "Bearer ...",
    "Cookie": "session=..."
  }
}
```

That is useful for programmatic integrations. It is not a replacement for the local "browser is the auth" path when you are acting inside the user's existing live session.

## If replay breaks

If the API moved or response shape changed, call [heal](/guides/heal/).

<Aside type="tip">
Unsurf can do both: use the browser to prove the flow, then use `worker` when the same stable HTTP seam is better reused directly.
</Aside>
