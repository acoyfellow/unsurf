`heal` belongs to Unsurf's reusable-seam path. It is what keeps `worker` useful after a website changes.

## Flow

```text
worker fails
   ↓
heal retries
   ↓
re-scout if needed
   ↓
return a repaired path
```

## Call heal

```bash
curl -X POST https://unsurf-api.coey.dev/tools/heal \
  -H "Content-Type: application/json" \
  -d '{
    "pathId": "path_lx1a_q7z2",
    "error": "GET /api/v1/users returned 404"
  }'
```

```json
{
  "healed": true,
  "newPathId": "path_mx2b_r8a1"
}
```

## What heal does

1. retries the original replay path,
2. marks it broken if the failure persists,
3. scouts the original site/task again,
4. verifies the replacement,
5. returns the new path.

## When to use it

| Situation | Use |
|---|---|
| A direct replay path drifted | `heal` |
| The browser task itself changed visually | update the browser plan or loop spec |
| The user-session task is still browser-native | stay on local browser MCP |

<Aside type="tip">
Healing repairs seams. It does not replace the browser runtime. If the site only works through the authenticated UI, record or loop in the browser instead.
</Aside>
