## Endpoint

The unsurf MCP server is available at:

```
https://unsurf-api.coey.dev/mcp
```

It uses the **Streamable HTTP** transport from the [MCP specification](https://modelcontextprotocol.io). The server runs in stateless mode — each request is independent.

For full documentation of all tool inputs, outputs, and error types, see the [MCP Tools reference](/reference/tools).

## Connecting from Claude Desktop

Add this to your Claude Desktop MCP config (`~/.claude/mcp.json`):

```json
{
  "mcpServers": {
    "unsurf": {
      "type": "streamable-http",
      "url": "https://unsurf-api.coey.dev/mcp"
    }
  }
}
```

Restart Claude Desktop. You should see **unsurf** listed under the MCP tools icon.

## Connecting from Cursor

Open Cursor Settings → MCP Servers → **Add Server** and enter:

| Field | Value |
|---|---|
| Name | `unsurf` |
| Transport | `Streamable HTTP` |
| URL | `https://unsurf-api.coey.dev/mcp` |

Cursor will discover the available tools automatically.

## Local browser MCP

Use the hosted MCP server for Cloudflare-side scout/search/plan work. Use the local stdio server when an agent should operate the Chrome session already open on your machine:

```json
{
  "mcpServers": {
    "unsurf-local": {
      "command": "unsurf-local-mcp"
    }
  }
}
```

The local server exposes two tools:

- `unsurf_local_sessions` — list attachable local Chrome/CDP tabs
- `unsurf_local_execute` — run small browser action plans against the active attached browser, optionally recording an unsurf trace

This is the "browser is the auth" path: the tool does not mint credentials or create a new browser profile; it uses the session you already authenticated.

## Connecting from a custom MCP client

Any client that supports the Streamable HTTP transport can connect. Point it at the `/mcp` endpoint and send standard JSON-RPC messages:

```
POST /mcp
Content-Type: application/json
Accept: application/json, text/event-stream
```

The server supports the `initialize`, `tools/list`, and `tools/call` methods.

## Testing the connection

You can verify the MCP endpoint works with plain `curl`.

### Initialize

```bash
curl -X POST https://unsurf-api.coey.dev/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2024-11-05",
      "capabilities": {},
      "clientInfo": { "name": "test", "version": "1.0" }
    }
  }'
```

You should get back a response with `serverInfo` and `capabilities`.

### List tools

```bash
curl -X POST https://unsurf-api.coey.dev/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc": "2.0", "id": 2, "method": "tools/list", "params": {}}'
```

The response lists the registered tools. The hosted server includes `scout`, `worker`, `heal`, `gallery`, `unsurf_search`, and `unsurf_execute`; `directory` and `agent-scout` appear when their optional bindings are configured.

## The trace-skill tool pair

Beyond the scout/worker/heal set, the MCP server exposes two tools that work with the record/observe/loop skills — a pair-pattern (search + execute) so agents have a small, stable surface to reason over:

### `unsurf_search`

List recorded traces. Filter by owner, task substring, or visibility. Returns `viewerUrl` values with grants pre-minted, ready to open.

```bash
curl -X POST https://unsurf-api.coey.dev/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "unsurf_search",
      "arguments": { "q": "httpbin form", "limit": 5 }
    }
  }'
```

### `unsurf_execute`

Run one of unsurf's Worker-safe skills. Today:

- **`loopPlan`** — synthesize a structured `LoopSpec` from a natural-language goal via Kimi K2.6. Plan only; no browser drive. Feed the result to the local `unsurf loop` CLI (or `loop()` JS API) to actually record.

```json
{
  "jsonrpc": "2.0",
  "id": 4,
  "method": "tools/call",
  "params": {
    "name": "unsurf_execute",
    "arguments": {
      "action": "loopPlan",
      "goal": "go to coey.dev, open the first project",
      "northStar": "Did the user land on a project detail page?"
    }
  }
}
```

Actions that need local Node APIs (actual `record()` via agent-browser, `observeVideo()` via ffmpeg) are CLI-only until the cloud recording provider lands (Phase 4 in [NORTHSTAR.md](https://github.com/acoyfellow/unsurf/blob/main/docs/NORTHSTAR.md)).

### Call a tool

```bash
curl -X POST https://unsurf-api.coey.dev/mcp \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "scout",
      "arguments": {
        "url": "https://jsonplaceholder.typicode.com",
        "task": "discover all API endpoints"
      }
    }
  }'
```

## Self-hosting

When you deploy your own unsurf instance, the MCP endpoint is automatically available at `/mcp` on your worker URL.

1. Clone the repo and install dependencies:
   ```bash
   git clone https://github.com/acoyfellow/unsurf.git
   cd unsurf && bun install
   ```

2. Set the required environment variables (see [Configuration](/reference/config#environment-variables)):
   ```bash
   export ALCHEMY_PASSWORD="your-secret-password"
   export CLOUDFLARE_API_TOKEN="your-cf-token"
   export CLOUDFLARE_ACCOUNT_ID="your-cf-account-id"
   ```

3. Deploy:
   ```bash
   bun run deploy
   ```

4. Point your MCP clients at your worker URL:
   ```
   https://unsurf.<your-subdomain>.workers.dev/mcp
   ```

<Aside type="note">
The REST API at `/tools/scout`, `/tools/worker`, `/tools/heal` is available alongside MCP on the same worker. You don't need to choose one or the other.
</Aside>
