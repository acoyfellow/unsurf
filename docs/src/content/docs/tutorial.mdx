The shortest path now uses **cmux's in-app browser**. `agent-browser` is not required for investigation, screenshots, portable repros, or broken/fixed confirmation.

<Aside type="note" title="When is agent-browser still needed?">
Only use the legacy attached-Chrome provider when you specifically need a playable local video or CDP-only evidence. cmux's WKWebView does not currently expose screencast recording, CDP traces, or network capture. Video is optional evidence; reproducible proof is the contract.
</Aside>

## 1 — Check the local provider

Open cmux, then run:

```bash
bunx unsurf doctor
```

Expected capabilities:

```text
cmux browser       ✓ ready
snapshots          ✓ yes
screenshots        ✓ yes
persistent auth    ✓ shared browser profile
isolated identity  ✗ no
video recording    ✗ no on cmux WKWebView; optional evidence
```

Sign in through the cmux browser as you normally would. Unsurf uses the browser profile you already trust; it does not mint or copy credentials.

## 2 — Investigate and confirm

Give Unsurf a vague symptom plus broken and fixed targets:

```bash
bunx unsurf investigate \
  --symptom "The response looked complete, then continued" \
  --broken "$BASELINE_URL" \
  --fixed "$CANDIDATE_URL"
```

Unsurf opens several explicit cmux browser surfaces, promotes only an observed candidate, and confirms it three times against each target.

```text
✓ PASS — fix confirmed
  candidates: 2/4
  broken:     3/3 reproduced
  fixed:      3/3 clean

  Repro:  .unsurf/runs/<id>/repro.json
  Report: .unsurf/runs/<id>/report.md
  Result: .unsurf/runs/<id>/result.json
```

## 3 — Replay the portable contract

```bash
bunx unsurf replay .unsurf/runs/<id>/repro.json \
  --target "$ANOTHER_PREVIEW_URL" \
  --runs 3
```

`repro.json`—not model prose—is the confirmation contract. The same artifact can move between previews and providers.

## 4 — Understand cmux isolation

A new cmux surface gets separate page/tab state, but surfaces currently share the Default WebKit browser profile.

```text
fresh cmux surface ≠ fresh browser identity
```

That is ideal for parallel authenticated exploration. For confirmation requiring clean identities, normalize application state, use separately configured profiles when available, or use Browser Run's isolated hosted sessions.

## 5 — Record video only when it helps

If the deliverable specifically needs a local MP4/WebM, use Unsurf's video-capable attached-Chrome provider. That legacy path currently uses `agent-browser`:

```bash
npm i -g agent-browser
agent-browser install
agent-browser --headed --profile ~/.unsurf-video open https://example.com
```

Then attach and record:

```bash
export TRACE_INGEST_TOKEN=...
bunx unsurf record ./demo.ts \
  --task "authenticated dashboard video" \
  --cdp-port 9222
```

See [Record a browser session](/guides/record/) for the complete video workflow. Browser Run is the hosted alternative and produces native rrweb session replay rather than MP4.

## 6 — Scout a reusable seam when HTTP is better

Some browser work reveals a stable hidden API. When repeated HTTP replay is better than UI driving, capture that seam:

```bash
curl -X POST https://unsurf-api.coey.dev/tools/scout \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "task": "find the search API"
  }'
```

Then replay it directly with `worker`, and use `heal` if the seam drifts.

## Mental model

```text
cmux browser interaction
        ↓
portable repro + independent confirmation
        ↓
optional video / session replay evidence
        ↓
optional typed API seam
```

Start with cmux. Add another provider only when its capabilities are required.
