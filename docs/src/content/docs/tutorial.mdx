This tutorial covers the shortest path through the current product:

1. start a real browser profile,
2. attach Unsurf to it,
3. record a proof run,
4. expose the browser through local MCP,
5. optionally scout a reusable API seam.

## 1 — Prepare the real browser

```bash
npm i -g agent-browser
agent-browser install
agent-browser --headed --profile ~/.cmux-browser open https://example.com
```

Sign in to whatever site you want to give agents access to. That profile is now your reusable authenticated workspace.

<Aside type="note">
Unsurf does not mint credentials for this path. It attaches to the browser you already authenticated.
</Aside>

## 2 — Record against the attached session

Create `demo.ts`:

```ts
export default async function run(browser) {
  await browser.goto("https://example.com/dashboard");
  await browser.wait(4000);
}
```

Then record it:

```bash
export TRACE_INGEST_TOKEN=...
bunx unsurf record ./demo.ts \
  --task "authenticated dashboard proof" \
  --cdp-port 9222
```

The result includes the trace metadata and viewer link. The browser stays open because Unsurf attached to an externally-owned session.

## 3 — Put the browser on MCP

```json
{
  "mcpServers": {
    "unsurf-local": { "command": "unsurf-local-mcp" }
  }
}
```

Your local agent now gets:

- `unsurf_local_sessions`
- `unsurf_local_execute`

That means nearby agents can discover the browser you already trust and ask it to perform small action plans.

## 4 — Close the loop when success needs verification

```bash
unsurf loop "open coey.dev, click projects, open the first one" \
  --north-star "Did the browser land on a project page?" \
  --max-iter 3 \
  --cdp-port 9222
```

Loop records, observes its own video, refines, and retries until the North Star is met or the budget ends.

## 5 — Scout a reusable seam when HTTP is better

Some browser work reveals a stable hidden API. When that happens, capture it:

```bash
curl -X POST https://unsurf-api.coey.dev/tools/scout \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com",
    "task": "find the search API"
  }'
```

Then replay it directly with `worker`, and use `heal` if the seam drifts. This is still part of Unsurf — just not the only story anymore.

## Mental model

```text
browser first
proof second
API seam when useful
```

That is the current Unsurf loop.
